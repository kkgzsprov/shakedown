# 6. 오라클, 탐색, 분류

M3는 QA 경로를 구현한다. 오라클과 실행 실패는 실행을 표시하고, 방문 수에 따른 샘플링은 다음 시도를 고르며, 측정된 이상 신호 비율은 조사할 그룹을 가리키고, 분류·재현은 재생 증거를 확인한다. 보고서는 신호·확인된 재현·누락된 증거를 구분한다. LLM 플래너는 M4 작업이다.


## 6.1 코드 오라클

오라클은 어댑터(adapter) 안에서 매 스텝 실행된다. 그래서 결정적이고, 실행과 함께 재생된다.

| 오라클 | 기본 규칙 | 동작 |
|---|---|---|
| 끼임 | 이동 전술 중 10 s 동안 0.5 m 미만 이동 | 정지, 종료 코드 4, `inputs.json` 보존 |
| 순간이동 | 한 스텝에 정해진 거리 이상 이동(프로토타입에서는 2 m) | 같음 |
| 수치 | 위치나 체력의 NaN 또는 Inf, 범위를 벗어난 체력, 음수 탄약 | 같음 |
| 월드 이탈 | 지형 아래 또는 맵 경계 밖 | 같음 |
| 적 월드 이탈 | NPC가 맵 경계 밖에 있음 | 같음 |
| 진행 없음 | 교전이 없는 상태에서 120 s 동안 새 방이나 웨이포인트 없음 | 경고만 |
| 크래시 | 프로세스가 비정상 종료 | 오케스트레이터가 테이프(tape)로 다시 실행하고 재현 여부를 기록 |

어댑터는 게임 고유 오라클을 추가한다. 열쇠 없이 열린 문이나 돈 없이 이루어진 구매가 그런 예다. 출발점으로는 playtest-agent의 범용 오라클 목록이 쓰기 좋다.

경계와 탐색 범위는 맵마다 정한다. 프로토타입에서는 주 필드에서 320 m 떨어진 지하 시설의 경비병까지 포함하려고 월드 경계를 450 m로 잡아야 했다. 또 탐색 웨이포인트를 고정된 ±200 m로 제한했더니, 작은 맵에서는 봇이 맵 가장자리로 갔다. 그러면 끼임 오라클이 맵 가장자리에서 발동할 수 있었다.

## 6.2 탐색

`shakedown explore`는 `--runs` 한도 안에서 시드가 고정된 계획을 먼저 만들고, 선택적인 `--deadline` 실제 시간 한도에서 멈춘다. 셀은 `(맵, 프로필, 디사이더, 변형)`이다. 방문 수에 따른 선택을 켜면 가장 덜 방문한 셀을 고르고, 동률은 시드로 결정한다. 셀마다 섞은 설정 시드 풀을 모두 쓴 뒤 시드를 재사용한다. 설정과 샘플러 시드가 같으면 실행 시간과 무관하게 같은 계획을 만든다.

`[explore].variants`는 이름과 인자 배열을 담는다. 어댑터가 시간대·장비·상황을 해당 인자로 노출할 수 있으며, Shakedown이 지원하지 않는 게임 플래그를 만들어 내지는 않는다. `--tuning-noise 1`~`3`은 검증된 키 표 안에서 값을 뽑고, 선택한 키와 값도 기록한다. `--no-steer`는 방문 수에 따른 선택을 끈다.

탐색은 마감 후 대기 중인 실행이 시작하지 않도록 순차 실행한다. 현재 실행의 시간 제한도 남은 예산으로 줄인다. `exploration.json`은 모든 계획 항목과 건너뛴 항목을 남기고, `batch.json`과 지표 분모는 실제 시도만 센다. 각 시도는 변형·인자·시드·튜닝·결과를 기록한다. 중단하면 현재 프로세스를 취소하고 시도를 보존하며 자동으로 재시도하지 않는다.

오라클 중단과 무효 시도는 `findings.jsonl`에 들어간다. CLI `run`과 `explore`는 아래 이상 신호 보고서도 쓴다. 제한된 실행 명령은 루트 README에 있다.

## 6.3 이상 신호

`anomalies.json`과 `anomalies.md`는 측정 비율, 기회 분모, Wilson 하한을 보고한다. 그룹은 설정한 `min_runs`(기본 5)를 만족하고, 95% Wilson 하한이 신호 임계값과 전체 측정 비율을 모두 넘을 때만 표시한다. `--baseline`은 별도 정상 배치를 기준으로 쓰며, 생략하면 같은 배치에서 전체 비율을 구한다. 그룹 자신과 비교한 것만으로 신호를 만들지 않는다.

기본 신호는 경고 없는 폭발 사망, 탈출 구역 시간 초과, 사망 원인별 비율, 빠른 접촉, 일반 시간 초과, 접촉은 있었지만 사격하지 않은 실행, 관측한 루팅 기회에서 루팅하지 않은 실행이다. 분모는 한 실행의 반복 이벤트가 아닌 측정한 실행 수를 센다. 무사격 신호에는 접촉과 발사 계측이, 무루팅에는 명시적 기회가, 탈출 구역 시간 초과에는 탈출 시도·측정한 구역 체류 시간·종료 시점에도 구역 안이라는 명시적 증거가 필요하다. 카운터와 이벤트가 모순되면 관측을 무효로 처리한다. 오라클로 관측이 끝난 실행과 무효 실행을 일반 행동의 성공·실패로 바꾸지 않는다.

`[anomalies]`에서 임계값·최소 수·그룹 기준을 정할 수 있다. 계측이나 기준 배치의 기회가 없으면 0이 아니라 `unmeasured`다. 양성 근거 실행 ID가 분류 단계로 연결되며, 재현 중에도 해당 조건을 다시 검사한다. 신호는 조사할 위치를 알려 줄 뿐 원인이나 버그를 확정하지 않는다. 분석기는 심어 둔 버그 플래그를 읽지 않는다.

## 6.4 분류·재현·클립

`shakedown triage`는 제출 목록, 소스 설정 해시, 실제 실행 증거와 발견을 대조한 뒤 묶는다.

1. **시그니처.** 오라클·실행 실패는 결과, 오라클 종류, 맵, 숫자를 지운 상세, 25 m 단위로 반올림한 위치를 쓴다. 이상 신호는 신호와 근거 맵·프로필·변형 그룹을 쓴다. 심어 둔 버그 이름은 시그니처에 들어가지 않는다.
2. **재현.** 새 시그니처의 첫 실행을 브리지 결정 테이프 또는 원래 규칙 실행 인자로 다시 돌리며, 추가 인자·시드·실행 시간·튜닝을 보존한다. 오라클·이상 신호 확인에는 게임 이벤트가 같은 독립 `inputs.json` 재생도 필요하다. 이상 신호는 같은 시간 초과·사망 결과만이 아니라 실제 신호 조건까지 재현해야 한다. 재생 assertion 코드 3은 확인이 아니다. 실행 실패는 해당 실패 종류와 증거를 맞추며, 로그나 실행 근거가 없으면 미측정으로 남긴다.
3. **초안.** M3는 증거·명령·마지막 이벤트로 결정론적 `bug_draft.json`을 쓴다. `suspected_cause`는 null이다. 플래너를 호출하거나 원인을 지어내지 않으며, LLM 초안 작성은 M4 작업이다.
4. **클립.** `--clips`를 주면 독립 입력 재생이 소스와 일치한 뒤 프레임을 클립으로 만든다. 기본 인코더는 tinyraid의 RGB8·비인터레이스·필터 0 PNG에서 애니메이션 GIF를 만든다. 지원하지 않는 입력은 미측정이고, 재생 불일치나 인코더 오류는 실패한 클립 시도다. 별도 인자 배열 인코더를 설정해 필수 의존성 없이 다른 형식으로 출력할 수 있다.

`findings/index.json`과 `findings/README.md`는 시그니처 상태와 소스 영수증을 보존한다. 같은 호출을 반복하면 소스 경로와 증거 해시로 중복을 제거한다. 새 근거 소스는 횟수만 갱신하며, 중단된 시도를 포함한 첫 재현을 암묵적으로 다시 시도하지 않는다. 카탈로그를 다시 열면 보존한 증거 해시로 기존 재현 판정을 재검증한다. 증거가 달라지거나 없어지면 자동 재시도 없이 미측정으로 바뀐다. 카탈로그는 `reproduced`, `unreproduced`, `unmeasured`를 구분하고 클립 상태는 별도로 남긴다. 분류는 게임 파일을 바꾸지 않는다.

예제의 `[clips]` 설정은 60 Hz 스텝 여섯 번마다 프레임을 요청해 10 fps를 만든다. 기본 10초인 마지막 시뮬레이션 구간을 선택하고 재생·프레임 증거도 보존한다. 선택적 `encoder_command`는 `{frames_dir}`, `{output_file}`, `{fps}`, `{seconds}`, `{python}`, `{project_dir}` 등을 치환하며 셸 없이 실행한다.

## 6.5 지표

배치가 끝나면 M2는 프로필 × 맵 × 튜닝 해시 × 디사이더별 `metrics.json`을 쓴다. 지표마다 실행별 값의 평균, 부트스트랩 95% 구간(`ci95`), 실제로 측정한 실행 수(`n`)가 있다. 부트스트랩 시드와 표본 추출 횟수도 기록한다. 관측 근거가 없으면 성공적인 0이 아니라 `mean: null`, `ci95: null`, `n: 0`이다. 관측이 하나이거나 관측값이 모두 같으면 부트스트랩 구간의 폭은 0이 된다. 이는 관측 표본의 특성이며 모집단의 확실성을 입증하지 않는다. 표본 실행이 모두 탈출에 성공한 경우도 마찬가지다.

제출된 배치 목록이 분모를 고정한다. 폴더 누락, 잘못된 텔레메트리, 계약 오류, 불일치, 크래시, 실제 시간 초과, 무효 브리지 요약은 `invalid_runs`에 남고 정책 비교에서는 제외한다. 구조적으로 유효한 오라클 중단은 `oracle_rate`에 포함한다. 그 실행의 생존·탈출은 정상 실패나 성공으로 세지 않고 관측 중단으로 처리한다.

게임 지표는 실제 텔레메트리에 있는 생존·탈출, 세션 길이, 첫 접촉, 접촉당 사망, 발사, 회복, 루팅을 쓴다. 먼저 본 주체나 보이지 않는 사수에 대한 증거가 없으면 해당 지표는 미측정이다. 발사 수를 임의 게임의 탄약 한 단위 소비와 같다고 가정하지 않는다. tinyraid는 지원하는 카운터를 `run_end`에 0까지 명시하므로 측정한 0과 계측 부재를 구분한다.

프레임워크 지표는 결정 영수증·테이프·브리지 요약에서 얻는다. 결정 수, 폐기 비율, 동일 전술의 최장 반복, 폴백 비율, 비용, 지연 시간을 포함한다. 셀의 지연 p50·p95는 실행별 백분위수의 평균이며 모든 호출을 합친 백분위수가 아니다.

짝 비교는 같은 프로필·맵에서 동일한 시드 ID를 맞춘다. 디사이더 또는 튜닝 중 하나만 바꾸며 둘을 동시에 바꾸지 않는다. 오른쪽에서 왼쪽을 뺀 차이와 짝 부트스트랩 구간을 보고한다. 셀 안에 중복된 시드는 모호한 시드로 나열하고 짝 추론에서 제외한다. 이 비교로 사람의 공정성이나 M3 버그 탐지 재현율이 입증되지는 않는다.
